# 平板声部切换后的播放回归

2026-11-14，0.6.7 / versionCode 17 已安装到实机并通过连续开关验证，已请用户辅助测试。

## 复现与原因

华为 DBY-W09、Android 12、华为 WebView 114 的冷启动可以播放。在暂停后切换谱表发声，音频 Worker 接收新的整首 MPE 事件时发生原生分配失败；后续 PrepareToPlay 无法响应。重新打开扬声器不会重新创建已中断的原生模块，所以直到关闭进程才能恢复。其他设备的成功结果不能替代这台平板的验收。

0.6.5、0.6.6 仅为本地测试包，均未修复实机问题，未发布 Release。释放过期缓存已减少占用，但单独这样处理仍无法保证替换整首事件的内存峰值。

## 本次实现

- 完整 MPE 事件保留在音频模块内。谱表的四个原生 PLAYBACK_VOICE 属性通过一个小掩码同步给音频 Worker，不再因发声开关重新传输整首乐谱。
- FluidSequencer 从已有数据更新较小的 MIDI 事件缓存，在相同播放位置继续。显示、隐藏与发声独立；已有的单声部开关、原生撤销和保存属性继续使用。
- 显示和声音变化只有在谱表 ID 顺序不变时跳过音频重建；增删、排序等结构变化仍刷新事件，避免套用错误的谱表索引。
- EventAudioSource 释放其已经交给合成器的初始事件引用，EventTrack 跟随当前事件更新，避免继续保留过期的整首乐谱。真实编谱变化替换事件前先释放旧缓存。
- 在启动阶段预留音频正常工作所需的空间，减少 32 位渲染进程晚期扩容失败；移动端交互画布限制分辨率，导出和整页 PNG 质量不受此限制影响。
- 处理 Worker 异常与后台音频恢复；播放、导入、切换和较慢操作提供旋转加载反馈。

## 验证

独立 Worker 的真实音频频谱验证已通过：高音、低音分别关闭，其他乐器继续发声；重新开启恢复，音频堆不随掩码变化增长。0.6.7 的完整桌面声部、MSCZ 保存、8 种布局、加载动画和光标测试均重新通过；187 个光标样本的最大误差约 13.54 ms，无音频缓冲欠载。

实机使用实际安装包，彻底关闭进程后启动，没有临时调试替换。`tools/verify-physical-playback.mjs` 使用实际 ADB 触摸、采样真实 PCM、检查时钟，并要求声部开关前后整谱事件发送次数不增加。平板原有 Sincerely MSCZ 连续八次开关通过，进度推进到 36.84 秒；全部静音时 PCM 为零但时钟继续，重新开启恢复声音。音频堆保持 234,881,024 字节，主堆保持 188,088,320 字节。测试结束恢复原有发声设置。
