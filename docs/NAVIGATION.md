# 0.6.2 标签状态与返回层级

## 修复原因

旧版 `musetab-back` 事件在同一个 window 上有多个监听者。父级 Library 可能先消费返回事件，使“外观”详情直接跳到“我的乐谱”。已在浏览器复现这一结果。

旧版分类与滚动数据属于 Library 组件，打开乐谱后组件被销毁，重建时全部重置。另有一个销毁时读取已断开 DOM 的问题，会把已保存的云端滚动位置覆盖为 0；新测试已覆盖云端详情 → PDF → 详情 → 列表的完整路径。

## 当前层级

- 设置详情 → 设置分组 → 我的根页 → 乐谱根页。
- 云端详情 → 云端列表。若从设置的“打开曲库”进入列表，再返回会回到该设置详情。
- 看谱 → 原来的列表或云端详情；编辑先返回看谱。
- 筛选、管理的子操作、解锁提示、设置弹窗、混音器、符号/选中面板先处理自己的返回，再由页面处理。
- 全屏内的子菜单先关闭；之后退出全屏，再返回看谱来源。PDF 批注状态先结束批注。
- 只有乐谱根页未打开子层时，才将返回交给 Android 退出应用。

`ui/back.ts` 用明确优先级及注册顺序分派，一次 Back 只由一个处理者消费，不再依赖同一 window 上的事件监听顺序。

## 状态范围

`library/view.svelte.ts` 独立于页面组件保存每个标签的格式、搜索、滚动及可见曲谱锚点；设置分组/详情和云端详情来源也保留。使用 sessionStorage 支持当前 WebView 会话内重载，未承诺跨进程冷启动恢复全部临时导航。

列表恢复等待 DOM 和数据准备完成，期间忽略布局收缩产生的滚动事件；手动操作可以接管。宽度变化时按曲谱锚点恢复。销毁时不读取已断开的滚动容器，避免覆盖为 0。不变更乐谱/文件/批注数据库结构。

## 已验证

- `verify-navigation.mjs`：手机/平板下切换标签、设置层级、详情来源、打开 PDF 后重建 Library、快速切换、延迟曲库加载、页面重载、筛选 Back、宽度变化锚点和根页退出判断。
- `verify-score-back.mjs`：实际 MuseScore 下菜单/设置/混音器、解锁提示与选中面板的分层关闭，以及全屏排版菜单 → 退出全屏 → 原列表。锁定时未改变音高。
- `verify-library-management.mjs`：重命名/导出/删除和云端详情下载回归。
- `verify-live-cloud.mjs`：真实静态曲库 573 份，分类与位置恢复，未使用 GitHub REST API。
- `verify-android-navigation.mjs`：MuMu Android 15，APK 0.6.2 / versionCode 12，使用 ADB `KEYCODE_BACK` 实际触发 Activity 返回；设置逐级返回、筛选和详情关闭、标签状态保留、设置到云端的返回来源均通过。该测试使用模拟器本地的曲库列表夹具，不下载夹具曲谱。

实体华为平板此前仍停留在锁屏/系统安装验证阶段，不能将模拟器结果作为该平板已升级或通过的证明。
