# 参考 Aria 重写编谱模式

> 已被用户的“编辑界面完全还原 Aria，配色除外”要求替代。当前执行标准见 [ARIA-EDITOR-FIDELITY.md](ARIA-EDITOR-FIDELITY.md)。下文保留为早期架构方案，不再作为界面交付标准。

状态：2026-11-15 已停止上一轮原生 QML 工作台构建；已开始实现替代方案的会话层。Aria 方式的新编谱页尚未完成，也未构建、安装或发布新的 APK。正式版保持 0.6.7。

## 参考版本与结论

参考仓库：[hdi200/aria](https://github.com/hdi200/aria)，固定提交 `9dffd7f3feea6d5af068723d5cfff47e7283a69c`。以下结论来自实际源文件；根 README 的版本描述比 Android 与引擎文档旧，不能据此判断当前核心版本。

Aria 的做法是把触屏界面、编辑状态和 MuseScore 排谱核心分开。界面按选中对象与输入任务显示工具，编辑通过有明确参数和返回状态的接口完成。MuseScore 仍负责乐谱数据、编辑语义、排谱和保存。它没有把桌面 QML 面板作为整个移动编辑界面。

MuseTab 采用这个分层方式重写独立编谱页。原生 QML 实验保留供对照；旧编辑器保留，不能用删除现有功能代替迁移。每项功能应有旧入口、新入口、引擎操作和验证记录，验证后再切换正式入口。

## 界面与功能组织

编谱继续作为单独一层进入，退出回到之前的看谱或播放界面。进入前保存页码、缩放和播放位置；返回键先退出当前输入或关闭弹层，再退出编谱。

- 顶部保留退出、撤销/重做、播放、锁定、保存及更多。默认锁定，锁在播放旁；修改请求先提示解锁，离开后恢复锁定。
- 主要区域显示 MuseScore 排出的谱面。点击选择、框选、拖动和双指缩放有独立处理；选择不应触发修改或无条件居中。
- 音符输入工具提供时值、休止、附点、升降号、延音线、连音线、连音组、声部与钢琴输入。
- 工具分类参考 Aria：选择、音符、和弦、歌词、指法、反复、文本、表情、排版、更多。选择对象决定当前可用操作及参数。
- 属性、符号、乐器与谱表、声部、混音器、页面与样式等现有能力逐项迁移。较少使用的功能可进入完整设置页，不能通过隐藏入口省掉功能。
- 平板宽屏允许谱面旁展开属性；窄屏使用可收起工具区。手机横屏单独组织控制列与输入键盘，不缩小整套桌面控件来适应屏幕。

视觉参考 Aria 的任务分组和触屏布局，乐谱符号与编辑结果来自 MuseScore。此前全局圆角规则不应用到编谱中的所有面板、遮罩和工具上；具体尺寸与外观随组件用途决定。

## 会话与桥接边界

以下为拟采用的契约，不是已经存在的 API：

```text
触屏编谱组件
  → ComposerSession：当前选区、输入意图、锁、忙碌/错误、保存修订号
  → 编辑命令队列：校验、按序执行、合并刷新、取消过时的预览
  → EngineAdapter：明确参数与类型化结果
  → 现有 MuseScore 核心：编辑、排谱、撤销、MSCZ 保存
```

命令需要说明是否修改乐谱；结果应包含选择、输入状态、撤销/重做能力、当前修订号和页面刷新范围。先映射现有桥接能力，再补齐缺口。保留低层 MuseScore action 的适配入口，但不让界面自行拼接状态并推断操作是否成功。

忙碌反馈应在进入排队或加载后及时显示。连续输入仍按顺序执行；不能为了隐藏卡顿直接丢弃用户输入。离开页面时，应取消过时预览与预取，同时等待已经接受的编辑及保存完成。

## 代码复用和 Android 边界

[Aria Android 文档](https://github.com/hdi200/aria/blob/9dffd7f3feea6d5af068723d5cfff47e7283a69c/MuseReaderAndroid/README.md)说明，其 Swift 原生逻辑通过 Skip Fuse 接入 Jetpack Compose，底层是 Qt/MuseScore C++。发布构建流程基于 macOS，Windows/Linux 主机构建尚未验证；该版本 Android 目标为 arm64-v8a。

首轮保留 MuseTab 的 Android 外壳、Svelte 界面运行环境和已验证的排谱/音频核心，在独立编谱层适配 Aria 的状态、命令、交互和缓存机制。SwiftUI 组件需要转换为现有界面的组件；不能直接导入后就视为完成复用。可复用的 C++ 能力及补丁应记录来源提交、版本差异和验证结果。

整套切换到 Aria 的原生 Android 引擎属于另一项平台迁移，需要先独立验证构建、设备兼容、文件读写和音频；不与这轮编谱界面改写捆绑进行。实际移植代码时保留 GPL、文件版权及相关第三方通知。

## 必须保留的现有行为

| 功能 | 迁移要求 |
| --- | --- |
| 看谱、全屏、播放及进度竖线 | 保留现有入口、翻页和音频时钟逻辑；编谱不得改写它们的状态所有权 |
| 声部显示与发声、混音器 | 独立设置，保留播放位置；不重现静音后无法播放的问题 |

| 旧编辑器和 QML 实验 | 保留源码作功能对照与回退；新入口逐项验证后再替代 |
| 曲库、云端、返回层级、外观 | 保持已有数据与功能；这轮只重新组织独立编谱层 |
| PDF 识别 | 保留已经完成的桌面离线基线；Android 集成仍是待办，识别结果进入同一编谱流程校正 |

## 实施顺序与完成标准

1. 建立旧编辑器、QML 实验与 Aria 的功能映射，接入独立会话状态和编辑命令队列。先验证选区、输入状态、撤销与保存，不删除旧实现。
2. 完成手机/平板的新编谱界面，贯通新建 → 点选 → 输入音符/休止符 → 修改 → 撤销/重做 → 保存 → 重新打开；验证默认锁和退出返回。
3. 迁移歌词、和弦、指法、文本、表情、反复、乐器/谱表、属性、页面与样式等功能。每项检查新入口、操作结果和保存后的完整性。
4. 接入页面预取、预览取消和按影响范围刷新，用用户提供的长篇 Animenz MSCZ 检查第二页之后点击、连续输入和翻页；记录实际耗时，不能只凭空白短谱判断性能。
5. 用手机和平板分辨率验证操作，并在问题平板回归播放、静音再播放、重新发声和退出编谱。达到功能与数据保留标准后再构建交付测试包。

### 当前实现进度

- `app/src/composer/session.ts` 已建立类型化 action/save 命令队列与引擎适配边界；界面忙碌反馈在同步 WASM 操作前获得刷新机会。
- 编谱菜单操作和手动保存已接入队列。导出、退出与模式切换等待会话中的已接受命令结束。
- 排队操作在执行前重新检查编辑锁与乐谱身份；失败时中止依赖它的后续命令并显示错误，不把这些操作应用到错误的选区。错误不阻断用户随后保存或退出。
- `TouchInput.svelte` 准备了触屏时值、声部和节奏工具组件，尚未挂入正式界面；当前仍显示保留的原生工作台。它不代表新界面已经完成。
- `node tools/verify-composer-session.mjs` 已覆盖连续命令/保存顺序、排队后重新锁定、乐谱切换、失败恢复及关闭隔离；`pnpm --dir app check` 为零错误、零警告。

当前串行化边界只包含已接入的界面命令，原生面板内操作仍由原有链路执行。当前桥接的 dispatch 为同步调用，返回的快照是调用后的现有引擎状态，不是新增的核心事务确认协议。输入意图、完整类型化编辑结果、页面失效范围以及原生面板迁移仍需继续实现；上述实机完成标准尚未执行。
